# 毫秒时基、模拟启动按键与无声播放器验证

日期：2026-10-06，Asia/Shanghai。专用测试台为 `fpga/sim/sc520-quiz-video/tb_quiz_runtime.sv`，不绑定外部按键或真实播放器。

实际正常运行 `runtime-normal-20261006-222026-6b8c8b66`：8场景、450065检查、0错误。实际负向运行 `runtime-negative-20261006-222336-317f0009`：同样450065检查、1个预期错误，退出1。两次输入快照、当前输入、输出hash、summary、transcript和退出码已由证据脚本的单项检查核对；最终总资格清单需包含四种测试各正负两项。

默认 `quiz_millisecond_tick` 使用 CLOCK_HZ=75000000；跨两次复位共检查150003个时钟周期，核对每75000周期一次使能，复位丢弃尚未完成的计数。另一个 CLOCK_HZ=1000 实例每拍输出使能，用于边界验证。测试台时钟采用名义75MHz，结论主要依据精确周期数，不把加速仿真时长当成实物测量。

模拟启动模块以 CLOCK_HZ=1000 加速。每个复位周期仅第1003和2003拍产生mode脉冲，多出的3拍来自复位同步和寄存后的tick传递；随后超过7万拍不再重复。两轮共4个脉冲。默认硬件配置约在复位后1秒和2秒切换模式，仍属于模拟按键，不能当作四个物理按钮已经实现。

模拟播放器使用 PLAY_TICKS=4 测试。接受请求后先产生ACK，ACK和接受拍不累加播放tick；ACK之后第4个tick才给曲终。stop优先于待发ACK、最后一个播放tick和新请求握手；保持stop只确认一次，释放后才重新ready。还验证busy期间不能替换活动tag，以及待ACK和播放中复位不会留下迟到响应。这是本地无声抽象，不证明真实器件支持相同协议或时序。

负向在第一次默认时基测试中实际强制输出tick为0，普通逐周期检查器发现应出现的第75000拍脉冲缺失；随后释放强制值。故障未注入RTL源文件，原输入hash保持不变。
