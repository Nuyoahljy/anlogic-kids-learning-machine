# 问答音频队列局部实现说明

任务：sc520-quiz-control。音频子代理负责 RTL 与专用测试台，根对话 `01a11124-e100-75e2-9e85-9f9686e23c73` 统一执行、汇总证据及登记。本文是本任务的局部设计说明，尚未冻结共享接口，也不代表真实模块验证。

## 输入与排队

`quiz_audio_queue` 使用单一 `clk`；`tick_1ms` 是同域的单周期毫秒使能。`event_valid` 每拍代表一件事件，携带 `event_kind[2:0]` 与 `event_item[3:0]`。调用方使用 1=名称、2=题目、3=正确、4=错误、6=清分、7=本轮结束；7 属于本地提案，共享文档中仍为保留。重播时再次提交实际的题目或名称事件，不使用一个依赖播放器内部“当前曲目”的命令。

默认容量是 8 件待播事件，此外最多有 1 件活动事务。队列不覆盖、不去重，因此“正确提示 → 下一题”和连续两次重播都保留顺序。满队列同拍出队和入队仍可接收；不能接收的新事件触发 `overflow` 与 `fault`，清除队列并停止已接受事务，避免静默漏题或错序。

## 设备抽象

`req_valid && req_ready` 的时钟上升沿才算设备接受请求，`device_busy` 会屏蔽 `req_valid`。等待期间 kind/item/tag 保持不变。此接口不是 AXI：取消、busy 或故障可撤销尚未接受的 `req_valid`，适配器在握手前不得开始发送或执行半条命令。

每次出队及明确拒绝后的重试获得新的 16 位 tag。`rsp_valid/rsp_tag/rsp_code` 最早在接受后的下一个时钟有效。code=0 是可确认的曲终；1 是明确保证尚未执行的拒绝；2 只是 ACK；3 是停止已经完成。错误 tag、ACK、BUSY 下降沿和未经请求的停止响应均不作为曲终。ACK 不重置播放超时。明确拒绝最多重试一次；二次拒绝锁存故障。

真实适配器必须把硬件协议转换成上述事实；不能把命令 ACK 冒充曲终，不能把不确定通信错误转换成“尚未执行”。tag 是有限的，适配器还必须保证迟到响应不会跨 65536 次事务回绕；控制器与设备适配器复位必须共同执行并清除旧响应。当前没有 UART、SD 文件序号或 GPIO 实现，没有声学输出。

## 取消与故障

`cancel` 优先丢弃同拍 event、清空待播，并屏蔽同拍新请求握手。未接受的请求可以直接撤销；已接受的请求转为 `stop_valid`，携带原 tag。`stop_valid` 保持到同 tag 的 code=3 或停止超时，code=0 和 ACK 均不能替代停止确认。取消期间新事件可以继续排队，只有停止确认后才可发送；重复 cancel 继续清待播但不延长停止截止时间。

默认等待、播放、停止超时分别是 1000、15000、1000 个 `tick_1ms`，均是可调局部实验参数，不是对任何真实播放器的断言。参数必须为正整数，`DEPTH >= 1`。握手、曲终或停止确认在各自超时边界优先；等待或播放状态的 cancel 又优先于当拍超时。STOP 状态的重复 cancel 不屏蔽停止超时。

等待超时不自动重试；播放超时发停止请求；停止超时终止本地等待并锁存故障。`fault` 及 `overflow` 只能通过共同复位清除，普通 cancel 不恢复故障。故障后事件被丢弃，`idle=1` 使问答显示和控制能够继续。这里的 idle 表示控制可以继续，**不能据此声称真实播放器已停止**：停止命令可能仍在等待确认，或者停止超时后其物理结果仍然未知。

## 专用测试入口

源码：`fpga/custom_project/sc520-quiz-control/quiz_audio_queue.v`。

测试台：`fpga/sim/sc520-quiz-control/tb_quiz_audio_queue.sv`，顶层 `tb_quiz_audio_queue`。专用测试用 DEPTH=4、WAIT=4、PLAY=6、STOP=3 缩短仿真，涵盖顺序、重播保留、九类 payload、全部本地事件类型、ready/busy、ACK、曲终、错误 tag、一次重试、二次拒绝、精确超时边界、取消、停止、满队列同拍出入、溢出、指令握手与溢出并发、活动状态复位。最终实际命令、结果计数和哈希以统一运行报告为准。

`+NEGATIVE` 在首题检查时真实 force 输出 kind=4，检查器仍按 kind=2 的正确预期检查并报告错误，再释放强制值。它证明输出检查器会发现损坏，不冒充 DUT 正常通过。
