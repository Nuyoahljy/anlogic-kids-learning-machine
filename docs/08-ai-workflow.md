# AI 与分支协作流程

## 1. 角色

主对话：

- 创建和关闭分支任务。
- 冻结接口和关键技术决策。
- 审核证据并合并 Git 分支。
- 更新总记忆、任务、决策、变更日志和稳定文档。
- 维护关键路径和周版本。

分支对话：

- 只解决一个明确任务。
- 在自己的 Worktree 中工作。
- 修改自己的日志、任务文件和证据。
- 记录真实命令、真实输出、阻塞和建议。
- 不直接修改主对话专属文件。

## 2. 标准循环

1. 主对话在 `TASKS.md` 中创建任务并创建分支日志。
2. 使用脚本创建 Worktree 和任务分支。
3. 分支对话先读必读文档，再写“进行中”。
4. 分支实现、仿真、上板并持续更新日志。
5. 分支执行验收，整理证据。
6. 分支把状态改为“等待主对话审核”并提交。
7. 主对话检查分支日志、差异、证据和回归结果。
8. 主对话用 `merge-task.ps1` 合并。
9. 主对话更新总记忆和任务状态，必要时打标签。
10. 主对话关闭分支，并把后续工作分配给新的任务。

## 3. AI 使用原则

- AI 可以生成 HDL 骨架、测试平台、脚本、文档和调试假设。
- AI 不能伪造综合结果、上板结果、照片、波形或识别率。
- 任何 AI 生成的 HDL 必须经过仿真或上板验证后再进入 `main`。
- 对无法验证的结论标记为“推断”或“待验证”。
- 关键模块的接口和约束由人复核，不能只依赖生成文本。
- 重要问题先查官方例程、数据手册和错误日志，再让 AI 生成替代方案。

## 4. 分支日志更新时机

至少在这些时点更新：

- 开始任务。
- 找到或修改关键接口。
- 完成第一次仿真。
- 完成第一次上板。
- 遇到阻塞。
- 完成最终验收。
- 提交分支前。

## 5. 主对话合并检查

- 分支日志状态为“等待主对话审核”。
- 差异只涉及任务允许的文件。
- 测试命令和结果完整。
- 证据路径真实存在。
- 失败和限制没有被隐藏。
- 合并后原始视频链路仍可运行。
- 必要决策已加入 `DECISIONS.md`。
- 必要任务状态和后续依赖已加入 `TASKS.md`。

## 6. 文档更新责任

| 信息 | 分支是否可写 | 主对话动作 |
|---|---|---|
| 分支日志 | 是 | 审核并保留 |
| 实验数据和脚本 | 是，限任务目录 | 验证并决定是否进入稳定文档 |
| 项目现状 | 否 | 合并后更新 |
| 任务状态 | 否 | 合并后更新 |
| 接口契约 | 否 | 接受提案后统一修改 |
| 关键决策 | 否 | 审核后新增决策 |
| 版本记录 | 否 | 合并后写入变更日志 |

## 7. 停止条件

出现以下情况时，分支应停止继续扩展功能并请求主对话决策：

- 需要修改共享接口。
- 需要引入新技术栈或额外处理器。
- 验收指标无法达到且需要缩小范围。
- 证据与分支描述冲突。
- 发现另一位成员正在修改同一模块。
