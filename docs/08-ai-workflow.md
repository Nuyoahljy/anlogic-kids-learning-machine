# 主对话总控与子任务协作

## 一轮的输入与输出

用户可直接说：开始今天这一轮，读取最新状态，推进最关键任务，并行安排一个不冲突的任务；完成后复核测试、整理 PR，等我确认合并。

总控输出仅需：当前步骤、最近实际结果、阻塞、待验收 PR、需要用户的下一动作。不填虚构百分比，不把“代理结束”记为任务完成。

## 总控循环

1. 读取根规则、索引、最新批次、项目总记忆、任务卡和日志；核对各 Worktree 的分支、HEAD、脏状态与归属。
2. 选择主线当前能做的工作，总控亲自处理眼前阻塞，例如与人核对接线；不要把关键阻塞交给代理后空等。
3. 将能独立并行的工作分给代理：明确工作目录、任务 ID、角色、精确文件范围、批准基线、输入、验收、停止条件和交接格式。
4. 执行过程中检查阶段产物和阻塞；主对话继续推进不重叠的工作，不频繁轮询。
5. 代理完成后先检查差异和权限，再独立重跑受影响测试，核对 HEAD、命令、退出码和证据哈希。失败退回原代理修复，不能只改结论。
6. 整理 PR 和验收层级，用户确认后才通过 GitHub 合并。合并后登记实际主库路径，更新总记忆和下一步任务。

短任务使用本轮子代理，由总控收集状态和结果；它们不必成为新的侧栏聊天。已有独立聊天可读其交接，若要继续向其派工，需要用户明确授权；不能自动接管旧写入者。

## 任务卡与权威来源

machine-readable 任务卡位于 memory/tasks。角色、路径白名单、必需检查由主对话批准，检查器从指定可信策略提交读取，不能信任任务分支自己扩大的权限。普通任务默认使用 main 的卡；首次流程升级使用主对话明确记录的 PolicyRef，不能把“任意当前 HEAD”作为通用绕过方式。

任务日志至少包含目标、输入、修改范围、实际命令/结果、证据、阻塞、待决策项和下一步。具体 CLI 与证据格式见 tools/README.md。

## 并发和边界

- 默认两个执行代理，必要时加一个只读审核，总数最多三个；不按人数盲目开满。
- 一条任务分支一个 Worktree、一个写入负责人。复用已有合适目录，不能清理别人未提交成果。
- 每台电脑同时最多一个 TD 和一个 ModelSim 任务，板卡同一时刻只有一个操作者。
- 本机主对话无法天然观察队友电脑或队友聊天；对方通过提交、PR、报告与证据链接交接。
- 按需总控只在用户发起的当前一轮运行，不创建定时自动化，不声称聊天停止后持续监控。

## 权限与人工确认

已授权：限定任务范围内的修改、自测、任务分支提交、推送和创建 PR。仍需用户确认：合并 main、变更冻结接口或方案、烧录/固化、修改接线或系统安全设置、处理不明旧改动及删除工作目录。

AI 不得编造综合或上板结果。现有 95.64% STA 覆盖不是约束完整性的证明；局部 RTL 仿真不是实际 720p 视频链路。纯文件/脚本 PR 可以按其任务标准接受，但不能据此更新硬件里程碑。

## 每日两人配合

你：执行一个可观察的上板步骤，保留镜像哈希与失败现象。队友：复现一个仿真或核对一组素材，记录输入输出和一项失败用例。收尾时各用几句话说明“实际做了什么、有什么证据、下一步卡在哪”，由总控统一安排，不互相拷贝整个工程目录。
